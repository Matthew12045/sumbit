# Register 6 — Official / minutes

**Scope:** This section applies ONLY when polishing meeting minutes, ministerial
memos, internal policy documents, or legal/regulatory texts.

## Hard rules for Register 6

### 1. formal-capability-frame

Use formal capability framing: describe what the document/decision DOES in
procedural terms, not what it "helps" with.

**Bad:** `การประชุมนี้ช่วยให้ทีมงานเข้าใจงานดียิ่ງขึ้้น`
**Good:** `การประชุมนี้เพื่อกำหนดแนวทางการทำงานและมอบหมายงาน`

### 2. formal-procedural-vocab

Use formal procedural vocabulary:

| Informal | Formal |
|----------|--------|
| ตัดสินใจ | พิจารณาและอนุมัติ |
| ทำ | ดำเนินการ |
| บอก | แจ้ง |
| ให้ | มอบหมาย |
| พูด | ระบุ / ชี้แจง |
| เห็นด้วย | ให้ความเห็นชอบ |
| ไม่เห็นด้วย | ไม่ให้ความเห็นชอบ |

### 3. four-part-procedural

Procedural sentences follow four parts:
1. **Time/bound** — `ในการประชุมนวดวันที่...` / `ในช่วงเวลาดังกล่าว`
2. **Subject** — `ที่ประชุม` / `ประธาน` / `ผู้แทน...`
3. **Action** — `พิจารณา` / `อนุมัติ` / `มอบหมาย`
4. **Object** — `รายงาน...` / `แนวทางการ...`

**Example:** `ในการประชุมนวดวันที่ 10 สิงหาคม 2569 ที่ประชุมพิจารณาอนุมัติรายงานผลการดำเนินงานไตรมาส 3`

### 4. time-bounds-need-anchor

Every action item must have a time anchor. No open-ended deadlines.

**Bad:** `มอบให้ทีม IT ดำเนินการปรับปรุงระบบ`
**Good:** `มอบให้ทีม IT ดำเนินการปรับปรุงระบบให้แล้วเสร็จภายในวันที่ 31 สิงหาคม 2569`

### 5. purpose-chain-required

When describing a decision, include the purpose chain: what → why → who → when.

**Bad:** `อนุมัติงบประมาณ 500,000 บาท`
**Good:** `อนุมัติงบประมาณจำนวน 500,000 บาท เพื่อดำเนินการปรับปรุงระบบสารสนเทศ โดยมี ผอ. IT เป็นผู้รับผิดชอบ และให้แล้วเสร็จภายในเดือนกันยายน 2569`

### 6. name-document-by-function

Reference documents by their formal name, not by shorthand.

**Bad:** `ตามรายงานที่เสนอ`
**Good:** `ตามรายงานผลการดำเนินงานไตรมาส 3 ที่เสนอในการประชุมครั้งก่อน`

### 7. no-telegraphic-shorthand

No abbreviated/telegraphic style. Full sentences, full names, full titles.

**Bad:** `ทิม IT ทำระบบให้เสร็จก่อนสิ้นเดือน`
**Good:** `ทีมสารสนเทศดำเนินการปรับปรุงระบบให้แล้วเสร็จก่อนสิ้นเดือนกันยายน 2569`

### 8. formal-issue-vocab

Use formal issue vocabulary:

| Informal | Formal |
|----------|--------|
| ปัญหา | ประเด็น / ข้อขัดข้อง |
| แก้ไข | แก้ไขปรับปรุง / ดำเนินการแก้ไข |
| เสนอ | เสนอต่อที่ประชุม |
| สรุป | สรุปผลการประชุม |
| สรุปว่า | มีมติดังต่อไปนี้ |

## Deixis for Register 6

- **No first-person.** Never use `ผม`, `ดิฉัน`, `เรา` (unless quoting a speaker).
- **No sentence-final particles.** No `ครับ`, `ค่ะ`, `นะ`, `นะค่ะ`.
- **Explicit subjects.** Every sentence must have an explicit subject — no zero anaphora.
- **Third-person only.** Refer to participants by name/title, never by pronoun.
