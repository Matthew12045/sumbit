# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **Shepherd workspace** (shepherd-agents/shepherd, v0.3.0) — not a library. The two Python files at the root are quickstart agent tasks that run sandboxed agents inside this directory. The framework itself is installed in the user site-packages (`shepherd`, `shepherd_dialect`, `vcs_core`) — it is not vendored here, and there is no build, lint, or test setup to run.

## Meeting Summary Discord Bot

The active project: a real, long-running Discord bot that joins a voice channel, transcribes the meeting live in Thai, and — when the last human leaves the voice channel — auto-posts a structured summary (Topics / Decisions / Action Items) to a configured text channel. It is built **with** Shepherd but does **not** use Shepherd at runtime (Shepherd is one-shot/sync; the bot is plain py-cord).

**Build flow (how the bot is produced).** `build_bot_task.py` is the Shepherd build driver: it registers `build.meeting_bot` and runs a jailed `claude` agent against the contract in `meeting_bot_spec.md` (the revised design). Review the retained result with `shepherd run changeset --latest --read <path>` and settle it with `shepherd run select <ref>`; edit the spec and re-run to iterate. `build_bot_task.py` must keep **both** monkeypatches — the `ClaudeHeadlessProvider.command_argv` `CLAUDE_CODE_TMPDIR` injection (jail, same as `agent_task.py`) **and** the `_WORKSPACE_RUNTIME_PROVIDER_TRANSPORTS.claude` budget override (see the budget gotcha below). The first build died at exactly 240s before the budget patch existed.

**Decisions (user-revised from the original design doc):**
- **Voice:** py-cord **pinned to the DAVE-patched unmerged branch** `git+https://github.com/Pycord-Development/pycord.git@fix/voice-rec-2` (PR #3159). Released 2.8.1 voice receive is broken under Discord's DAVE end-to-end encryption (issue #3139) — don't "fix" this pin back to a release, capture will silently stop. A watchdog warns if no PCM frames arrive after recording starts.
- **STT:** local `mlx-whisper` (`mlx-community/whisper-large-v3-mlx`, `language="th"`) — free, Metal-accelerated on Apple Silicon; shares the GPU with the gateway stack. Default is the **non-turbo** large-v3 because large-v3-turbo enters confident repetition-loop hallucinations on Thai (the 2026-08-09 empty-summary bug); turbo is selectable via `WHISPER_MODEL`. `transcriber.py` hardens the decode (`condition_on_previous_text=False`, T=0 greedy) and re-decodes once with a small temperature bump + Thai preamble when a decode is flagged garbage — watch for `recovered after anti-loop retry` vs `still garbage after anti-loop retry` in the logs. mlx's `compression_ratio_threshold`/`logprob_threshold` fallback gates never trip on confident loops (low compression, high avg_logprob), so they are intentionally **not** passed — don't "add" them back in. Beam search is plumbed via the `WHISPER_BEAM_SIZE` env knob but **defaults to 0 (greedy)**: the installed mlx-whisper raises `NotImplementedError` for `beam_size > 1`, and its `best_of` alternative is incompatible with T=0 greedy — see the toggle notes below. The FLEURS Thai A/B harness (`tools/e2e_whisper_compare.py`) measures candidate models against the current default with production-mirroring decode kwargs; see "STT A/B benchmark" below for the measured table and adoption verdict.

**STT A/B benchmark** (`tools/e2e_whisper_compare.py -n 50 --seed 42`, Google FLEURS Thai). The harness decodes WAVs as float32 numpy arrays (production-style input — mlx-whisper shells out to ffmpeg for file paths, and this machine has none) and mirrors production decode kwargs (T=0 greedy, `condition_on_previous_text=False`, `beam_size` only when `WHISPER_BEAM_SIZE` > 1) — its old `compression_ratio_threshold=0.01` gate forced temperature fallbacks on nearly everything and was removed. Candidate conversion: `python3 tools/convert_typhoon_to_mlx.py` → `/tmp/typhoon-whisper-large-v3-mlx` (~2.9 GB fp16; `/tmp` means it does not survive reboots — rerun the converter if missing; it transposes conv kernels to MLX layout and casts to fp16, both required or decoding fails with a conv-shape / dtype error). Measured **2026-08-25, n=50, seed=42**:

| metric | current `mlx-community/whisper-large-v3-mlx` | candidate `typhoon-ai/typhoon-whisper-large-v3` (MLX) |
|---|---|---|
| CER mean | **0.1285** | 0.1479 (+15.1% worse) |
| CER median | **0.0783** | 0.1010 |
| decode time mean | 4.17 s | 3.82 s |
| garbage flags / loop flags | 0 / 0 | 0 / 0 |
| per-sample CER wins | 26 | 24 |

**Verdict: KEEP `mlx-community/whisper-large-v3-mlx`.** The adoption rule required ≥10% relative CER improvement with no garbage-rate regression; the candidate is ~15% worse on FLEURS Thai. No config change.
- **Summarization:** the user's own gateway via the Anthropic-compatible API — `anthropic` SDK with `base_url=https://gateway.9arm.co`, `auth_token` (`ANTHROPIC_AUTH_TOKEN`), model `qwen3.8-27b-fp8` (quantized variant, 128k-token context; user-verified working in Claude Code on 2026-08-25 — expect a long silent thinking phase before the response). **Do not append `/v1` to the base URL** (the SDK adds it). The call is a **blocking** `messages.create()` — the gateway buffers completions server-side, so streaming adds no early-abort value and `SUMMARIZE_TIMEOUT_SECONDS` (300) is the ceiling. The completed output is checked post-hoc for an exact-repeat loop (`REPETITION_WINDOW_CHARS=300`, `REPETITION_MIN_REPEATS=3`); a loop raises `StalledGenerationError(progressed=True)` and posts a visible ⚠️ note via `bot.py`. Retry policy: retry once **only** on `APITimeoutError` — `EmptySummaryError` and the loop error are never retried, since re-running temperature=0 against the same reasoning trace would reproduce them. Budget defaults: `MAX_PROMPT_CHARS=135000` (declared **128k-token window** on the fp8 variant; measured 2026-08-25 at ≈1.23 chars/token for Thai prompt text and ≈0.80 for output — 135k chars ≈110k tokens, ~18k-token headroom for system + full output), `SUMMARY_MAX_TOKENS=8192` (richer schema + qwen thinking). The output schema carries context, not labels: `overview`, `topics` (`title`+`detail`), `decisions` (`decision`+`rationale`), `action_items` (`action`+`owner`+`due`), `open_questions`. An empty completion (`EmptySummaryError`) also posts a visible ⚠️ note via `bot.py`.
- **RAG summarization:** per-meeting retrieval replaces plain truncate-and-summarize by default (`RAG_ENABLED=true`). See the RAG section below.
- **Kien-thai polish:** the OpenTyphoon-backed Thai-writing audit+fix loop stays on OpenTyphoon (`typhoon-v2.5-30b-a3b-instruct`) — user decision: a Thai-trained model judges Thai prose. Enabled live via `POLISH_ENABLED=true`; see the polish section below for its fixed failure semantics.

**Bot layout** (`meeting_bot/`): `config` (`.env` → frozen dataclass + `doctor()`), `audio` (48k-stereo-int16 → 16k-mono-f32 numpy resample), `chunker` (silence segmentation), `sink` (py-cord per-user capture), `transcriber` (single worker thread → mlx-whisper), `transcript` (speaker/time events), `rag_store` (per-meeting chunking + cosine index, numpy-only), `embedder` (local MLX sentence embeddings, lazy import), `summary_parse` (robust parse), `summarizer` (blocking gateway call), `thai_polish` (OpenTyphoon audit+fix loop), `poster` (embed + markdown attachment), `bot` (`MeetingBot(discord.Bot)`, auto-trigger on voice-channel-empty + `/leave`//`/join` slash commands), `main`/`__main__`. **Import rule:** `config`/`audio`/`chunker`/`transcript`/`summary_parse` **+ `rag_store`** import only stdlib + numpy at module scope, so the jailed agent can smoke-import them and `pytest` runs without Discord/MLX/anthropic.

**Lazy import pattern (`meeting_bot/__init__.py`).** The package uses `__getattr__`/`__dir__` to defer importing `Config` (from `config`), `MeetingBot` (from `bot`), and `ThaiPolisher` (from `thai_polish`) until they are first accessed. This keeps `import meeting_bot` lightweight — the heavy deps (`discord`, `mlx-whisper`, `anthropic`, `openai`, `mlx_embedding_models`) are never loaded until the bot actually runs. The pure modules (`config`, `audio`, `chunker`, `transcript`, `summary_parse`, `rag_store`) are importable with only numpy present, so `pytest` runs in a minimal environment.

**Diagnostic modules:** `meeting_bot/_pycord_diag.py` applies 7 monkeypatches for DAVE encryption (passthrough mode, UDP keep-alive EISCONN fix, etc.). `meeting_bot/wav_dump.py` writes each whisper input chunk as a 16 kHz mono WAV when `DUMP_CHUNKS_DIR` is set — used with `tools/offline_repro.py`, the A/B harness for testing decode strategies against real captured audio.

**Summary parser (`summary_parse.py`).** The JSON→markdown→raw fallback parser is the key reliability mitigation for qwen's structured-output unreliability. Schema: `overview`, `topics` (`title`+`detail`), `decisions` (`decision`+`rationale`), `action_items` (`action`+`owner`+`due`), `open_questions` — all with Thai key aliases (`ภาพรวม`, `หัวข้อ`, `การตัดสินใจ`, `เหตุผล`, `รายละเอียด`, `คำถามที่ยังไม่ได้ข้อสรุป`). Parse order: (1) JSON with Thai/English key tolerance and prose-stripping — plain-string `topics`/`decisions` from the old schema still wrap into `TopicItem`/`DecisionItem` with empty detail/rationale; (2) markdown header fallback (`ภาพรวม`/`Overview`, `หัวข้อ`/`Topics`, `คำถามที่ยังไม่ได้ข้อสรุป`/`Open Questions`, etc.), splitting `title — detail` / `decision — rationale` bullets on a `:`/`—`/`–` separator; (3) last resort — raw text becomes the `overview`. Never raises.

**Voice trigger logic (`bot.py`).** `MeetingBot` extends py-cord's **`discord.Bot`** (subclasses `Client`; verified the pinned DAVE commit forwards `intents=` through `**options`, so `run(token)`/events are unchanged — no Message Content intent). In `on_voice_state_update`, count **humans only** (`[m for m in channel.members if not m.bot]`). Start meeting when humans are present and not connected. Finalize when target channel has no humans and bot is connected. When a human leaves but others remain, call `sink.flush_user(member.id)` to flush their trailing audio. Race guard: `_meeting_active` flag + lock; re-check humans before disconnect; member joining mid-finalize won't double-post.

**Manual `/leave` + `/join` slash commands.** Guild-scoped (`guild_ids=[cfg.guild_id]` → instant sync), registered idempotently in `__init__` via a guard flag, anyone may invoke. `/leave` acks immediately (`ctx.respond` — interaction tokens die in 15 min) and spawns `_finalize(channel, force_disconnect=True)` as a background task; forced finalize sets `_manual_leave = True`, **skips** the humans-present keep-connection race-guard branch, and always tears down + disconnects; with no meeting active it just disconnects any lingering client and replies "ไม่มีการประชุมอยู่ตอนนี้". While `_manual_leave` is set, auto-start is suppressed until the target channel is observed with zero humans (then normal auto-rejoin resumes) — the gate is the pure function `rejoin_allowed(manual_leave, human_count)` (unit-tested in `tests/test_bot_rejoin.py`). `/join` clears the flag, acks ephemeral, and spawns `_start_meeting` when humans are present.

**RAG summarization (`rag_store.py` + `embedder.py`, wired in `bot._build_prompt`).** When `RAG_ENABLED=true` (default), finalize no longer sends the whole truncated transcript: the transcript is rendered into `[MM:SS] speaker: text` lines exactly like `Transcript.to_prompt_text`, chunked into line-aligned sliding windows (`RAG_CHUNK_CHARS=800`, never splitting a line; trailing lines totalling ≤`RAG_OVERLAP_CHARS=150` repeat for context), embedded locally with `mlx_embedding_models` + `BAAI/bge-m3` (~2 GB first-run HF download; symmetric model, no prefixes), indexed in a brute-force L2-normalized cosine index (`VectorIndex`), and retrieved by a **fixed five-query Thai set** (overall gist / topics / decisions / action items & owners / unresolved questions). `query_multi(vectors, RAG_TOP_K=8)` unions top-k per query, dedupes by chunk keeping max score, and re-sorts chronologically so the excerpt reads in meeting order. The joined block is hard-capped at `MAX_PROMPT_CHARS` with `truncate_block` (mirrors `to_prompt_text` truncation semantics). Everything runs inside the same `asyncio.to_thread(_summarize)` closure (the embedder may load a ~2 GB model off-loop); any failure logs a warning and falls back to the legacy full-transcript truncated path — posting is never blocked. `RAG_ENABLED=false` reproduces the legacy prompt byte-for-byte. Per-meeting index only; nothing persists across meetings.

**Sink audio grace window:** After each `channel.connect()`, `bot.py` calls `sink.set_grace_until(monotonic + N)` to drop incoming PCM frames while DAVE derives per-sender decryption keys. Frames in this window would fail `NoValidCryptorFound` and corrupt the chunker. The grace timer is re-armed on mid-meeting reconnects too.

**Kien-thai polish (`thai_polish.py`, fixed 2026-08-24).** The audit+fix loop polishes only `overview`, `topics[].detail`, and `decisions[].rationale`; **protected fields** (topic titles, decision labels, action_items, open_questions) are always taken from the original summary regardless of model output. Two bugs were fixed: (1) `_parse_polished` used to return an empty `edits_needed=False` result on malformed JSON, which `polish()` then rebuilt into a **gutted empty summary** — it now raises, and `polish()` catches and returns the ORIGINAL; shape violations (missing fields, wrong types, topics/decisions count ≠ input) also raise. (2) Convergence no longer compares reconstructed raw markdown strings — it compares field snapshots (`overview`, topic details, decision rationales) between passes: zero diffs ⇒ converged; `edits_needed=false` accepts the final edit unless the model blanked out previously-nonempty text (`_blanks_text` guard). Failure modes are distinguishable in logs: `converged after N pass(es)` / `accepted final edit` / `hit safety cap` / `hard failure … returning original`. Never raises past the module; `bot.py` posts unpolished on failure.

**Poster (`poster.py`).** `build_embed()` constructs the Thai-language embed as a *scannable index* (description = `overview`; `• **title** — detail` bullets; an `open_questions` field; footer with duration/member count). Discord caps the **sum** of title + description + all field names/values + footer at 6000 chars, so the description and the four field values are carved from one shared pool: fixed text (title, field names, footer) is counted first and `_fit_to_pool()` proportionally scales the desired per-piece budgets (description ≤ 2000, fields ≤ 1024 each) against the remainder — a genuinely rich meeting scales everything down instead of blowing the total and getting a 400 from Discord. Truncation appends a `…ดูรายละเอียดเพิ่มเติมในไฟล์แนบ` note. The *complete* untruncated summary — full `detail`/`rationale`, action-item table, all open questions — is attached as `summary.md` (Markdown) in the same `channel.send(embed=…, file=…)`. `Poster.post()` retries up to 3× on 429/5xx, rebuilding the `discord.File` per attempt (a failed send consumes the buffer).

**Build contract (`meeting_bot_spec.md`).** This is the authoritative architecture doc and module contract that `build_bot_task.py` feeds to the jailed claude agent. Every class, function signature, import rule, and acceptance criterion is defined here. After `shepherd run select`, verify the 6 acceptance criteria from the spec: (1) `compileall` exits 0, (2) pure modules import with only numpy, (3) `--help`/`--doctor` work without connecting, (4) all documented signatures exist and `.env.example` matches `config.py`, (5) no secrets in any file, (6) `.env.example` keys match `config.py` exactly.

**Whisper decode / diagnostic toggles (runtime env, not `Config` keys):**
- `DUMP_CHUNKS_DIR=<dir>` — write every chunk the transcriber receives as a 16 kHz mono `.wav` (`{speaker}_{start}_{dur}s.wav`) **before** decoding, so a failed live run leaves inspectable audio. Inert when unset. ~1.9 MB/min/speaker.
- `WHISPER_FP16=1|0` — whisper fp16 compute (default 1). Must be constant for a process (mlx caches the model by path only): set it before the first decode and restart to change. `0` is a numerics experiment (roughly doubles memory).
- `WHISPER_RETRY_TEMPERATURE=0.2` — sampling temperature for the anti-loop retry decode.
- `WHISPER_INITIAL_PROMPT=` — Thai preamble for the anti-loop retry; empty value disables it. Retry-only, so it can never bias a clean first decode.
- `WHISPER_BEAM_SIZE=0` — beam-search width for whisper decoding (>1 enables beam search, 0/1 = greedy). **Default is 0**: the installed mlx-whisper raises `NotImplementedError("Beam search decoder is not yet implemented")` for `beam_size > 1`, and its `best_of` alternative is incompatible with T=0 greedy, so grouped decoding is unavailable until mlx-whisper implements it. The plumbing is verified end-to-end (kwarg flows through `transcribe(**decode_options)` into `DecodingOptions.beam_size`); flip the knob after upgrading mlx-whisper.

These are read via `os.environ` by `transcriber.py`/`wav_dump.py`, so they can live in `.env` (loaded with `override=True`) or be shell-exported. They are deliberately NOT in `.env.example` / `Config` to keep spec acceptance criterion 6 (`config.py` keys ⇔ `.env.example` keys) airtight.

## Architecture

**Task model.** A task is a Python function whose *signature is the permission surface*: type-annotated parameters (e.g. `repo: sp.GitRepo`, `output_path: str`) declare what the sandboxed agent may access or write, and the docstring is the contract the agent implements — the body is intentionally empty. Register on a workspace via `workspace.tasks.register(task, task_id="…")` or the `@sp.task` decorator.

**Run lifecycle.** `with sp.open(".") as workspace:` binds the workspace; `workspace.run(task, repo=workspace.git_repo(), …)` executes the task in an isolated fork and returns a run whose `.output()` exposes the retained result (`.changeset()`, `.read_text()`, `.release()`). Runs never write your working files — output lives in the retained store until `shepherd run select`.

**Providers.** `runtime={"provider": "static"}` is a deterministic no-LLM provider that works with `placement="advisory"`. `runtime={"provider": "claude"}` shells out to the headless `claude` CLI inside the OS jail and *requires* `placement="jail"` (advisory is rejected for it). `jail` wraps the run in a macOS Seatbelt sandbox; `advisory` skips OS-level enforcement.

**The jail's writable root (critical).** Under `jail`, the run's only writable path is its ephemeral clone dir — a `vcs-core-overlay/…/clones/<run-scope>` tree under the system temp dir, **not this repo**. `agent_task.py` exists around this constraint: the `claude` CLI unconditionally `mkdir`s `/tmp/claude-{uid}` at startup, which the jail refuses (EPERM). The file's header comment and its `ClaudeHeadlessProvider.command_argv` monkeypatch inject `CLAUDE_CODE_TMPDIR=<working_path>/.claude-scratch` into Shepherd's env redirect so that mkdir lands inside the writable root. Don't simplify that monkeypatch away, and don't "fix" the EPERM by pointing `CLAUDE_CODE_TMPDIR` at this repo's path — the repo is outside the jail.

**.vcscore/.** The workspace's internal object store (analogous to `.git`), created by `shepherd init`. It is untracked runtime state, not source. A `.gitignore` now covers `.vcscore/`, `__pycache__/`, `*.pyc`, `.pytest_cache/`, and `.env` (bot secrets). The repo still has no commits — before the first commit, `git status` should now show only source files.

## Gotchas

- **Gateway Cloudflare 524 ceiling (diagnosed 2026-08-25 via `tools/gateway_test_matrix.py`).** gateway.9arm.co sits behind Cloudflare whose **proxy read timeout (~120 s per byte-gap)** killed every summarization-sized completion on the non-fp8 `qwen3.8-27b` (~6–7.5 tok/s effective; streamed bodies died mid-flight at ~126 s because nothing flows during qwen's silent thinking phase, and non-streaming calls 524'd at exactly 120 s). On 2026-08-25 the bot switched to `qwen3.8-27b-fp8` (user-verified in Claude Code), which **completes the full production-shaped summarize call in ~29 s** and passes the fast battery 7/7 (tiny probe 1.3 s, small output ~23 tok/s, 150k-char input accepted in ~5 s, old model still 403). The streaming keep-alive gap remains architecturally unfixed — if generation times creep back past ~120 s, re-run `python3 tools/gateway_test_matrix.py --slow` and expect the same idle-between-bytes kill (`message_start` arrives at ~0.2 s but no bytes follow during thinking); the operator-side ask is to emit SSE keep-alive comments or forward thinking deltas live, after which `Summarizer` should switch to streaming mode (a deliberate amendment to the blocking-create decision, pending need). Nothing client-side helps when a single generation exceeds the window: `/no_think` was tested in both system and user placement without effect, smaller `SUMMARY_MAX_TOKENS` yields empty summaries, retries don't help. Old model `qwen3.6-35b-a3b` remains 403 (off allowlist).

- **mlx_embedding_models × transformers≥5 shim.** `mlx_embedding_models` 0.0.11 tokenizes via `tokenizer.batch_encode_plus`, removed in transformers 5.x — `Embedder.__init__` monkeypatches the model instance with an equivalent `_tokenize` (modern `tokenizer(...)` API) only when the legacy method is absent. bge-m3 quality verified through the shim (related/unrelated Thai cosine ≈0.85/0.44, dim 1024). Expect the harmless warning "model of type xlm-roberta to instantiate a model of type bert" — bge-m3 IS xlm-roberta and loads/works fine.

- **Session-reuse masking.** A `claude` spawned from inside a running Claude Code session inherits `CLAUDE_CODE_SESSION_ID` and reuses the parent's existing workspace, skipping the startup mkdir — so runs launched from inside this session can pass when a fresh terminal would fail. - claude-provider runs need network + auth inside the jail; Shepherd sets `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, but real API traffic is allowed.

- **Build budget cap.** `ClaudeHeadlessProvider` defaults to `budget_seconds=240` (a SIGALRM hard stop) and the runtime envelope *reserves* that field, so you can't pass a bigger budget through `workspace.run(runtime=...)`. `build_bot_task.py` replaces the module-level `_WORKSPACE_RUNTIME_PROVIDER_TRANSPORTS.claude` transport (the same private seam the framework uses for test transports) with one that passes `budget_seconds` from `SHEPHERD_BUILD_BUDGET_SECONDS` (default 1800). Don't simplify this away — a whole-package build dies at 240s.
